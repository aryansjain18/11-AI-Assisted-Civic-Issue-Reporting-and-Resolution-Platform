# 06 — UI, UX, and Accessibility

## Experience goals
- Clear, trustworthy, civic-oriented visual language.
- Mobile-first responsive layouts.
- Simple report submission.
- Clear status labels and explanations.
- Separate citizen and administrative workflows.

## Required interface states
- Loading.
- Empty results.
- Validation errors.
- Submission success.
- Network/server failure.
- Unauthorized access.
- Upload progress/failure where uploads exist.

## Accessibility baseline
- Semantic HTML and meaningful headings.
- Programmatic labels for every form control.
- Keyboard-operable navigation and controls.
- Visible focus indicators.
- Sufficient text and control contrast.
- Status is not communicated by color alone.
- Useful alt text for meaningful images; decorative images are ignored by assistive technology.
- Accessible error summaries and inline error associations.
- Respect reduced-motion preferences.
- Test narrow viewports and keyboard-only navigation.

## Design consistency
Use a small documented set of spacing, typography, color, radius, and component patterns. Avoid decorative complexity that harms readability.
